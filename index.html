Open the suspicious email. Just not on your own machine.

PhishRange is a Claude Code tool that triages phishing and malware on a single Windows PC. It parses the email, runs any attachment inside two throwaway VirtualBox sandboxes, has six specialist agents read the evidence in parallel, and hands you a plain-English verdict with the actions to take.

Think of it as a one-person SOC for a family inbox: no malware lab, no cloud sandbox subscription, and nothing leaves the PC except optional reputation lookups.

1command, /phish-scan
2sandbox clones per attachment, run in parallel
6analysis agents, dispatched together
0actions taken automatically
Working end-to-end. Golden VM built and snapshotted, full pipeline run against a benign fixture, 52 of 52 tests passing.

Scripts gather the evidence. Claude reads it.

Anything that must behave the same way every run, like parsing, hashing, VM control, API calls and the database, is a plain Python or PowerShell script with tests. Claude is used only where judgement is needed: reading the evidence and explaining it. The two layers never call each other directly. They meet in one case folder on disk.

Same sample, two network postures, at the same time.

Every attachment runs in two fresh clones of a read-only golden Windows 11 snapshot. One has no network at all, which shows baseline behaviour with no risk of a callback. The other can reach the internet through its own NAT network, which exposes the C2 beacons and second-stage downloads that network-aware malware hides when it's offline.

Six analysts, each with one job.

Each agent reads only its slice of the case folder and writes one findings file shaped as {"risk_score": 0-10, "summary", "details"}. All six treat every header, filename, body and screenshot as attacker-controlled data. A prompt-injection attempt hidden in a sample is recorded as a finding, not obeyed.

The worst finding sets the verdict.

synthesize.py doesn't average. Severity is the highest score any single agent gave, so one strong signal, like a known-bad hash, can't be diluted by five quiet ones. A missing or malformed findings file counts as 0 and is noted in the report. Move the sliders to see how it plays out.

    Set up once, then scan in one command.

    The golden VM is the only slow part, about 20 to 40 minutes of unattended install, and you only do it once. Every case after that clones from the snapshot.

    You'll need

    • Windows 11 with VirtualBox 7.2Built against the 7.2 CLI; see vm-setup/README.md before using older guides.
    • A Windows evaluation ISOPlus the free ADK Deployment Tools (oscdimg.exe) to bake in the answer file.
    • Python 3.11 or newerrequests, python-dotenv, pytest
    • Claude CodeThe pipeline runs through /phish-scan and its subagents.
    • Free API keys, optionalVirusTotal, urlscan.io, AbuseIPDB. A missing key, rate limit or network error returns an "unavailable" result instead of failing the case.

    1. Build the golden VM

      Fill in autounattend.xml from the template with your ISO's edition name and a throwaway password, then run the two build scripts. The result is PhishRange-Golden with a golden-clean snapshot.

      .\vm-setup\vm_build.ps1
.\vm-setup\vm_build_finalize.ps1

    2. Install Python dependencies

      pip install -r requirements.txt

    3. Add API keys, if you have them

      Fill in any of VT_API_KEY, URLSCAN_API_KEY and ABUSEIPDB_API_KEY. Leave any blank to skip that source. .env is git-ignored.

      Copy-Item .env.example .env

    4. Run a case in Claude Code

      Drop a .eml into intake/ and run the command with no arguments, or paste the email after it. Cases with an attachment take several minutes while both sandboxes run.

      /phish-scan

    52 tests, and none of them touch the network.

    conftest.py forces all three API keys to None for every test, so the no-key paths are always exercised and no test makes a live call, whatever is in your .env. The VM scripts are checked by hand against real VirtualBox, and the smoke test is a full run against tests/fixtures/benign-test-phish.eml.

    What it doesn't do yet.

    These are deliberate scoping decisions for this version, recorded in full in section 9 of the design spec.

    Known gap

    Samples launch outside the desktop session

    guestcontrol start runs the sample in the non-interactive Services session, confirmed with tasklist. Screenshots show the idle desktop rather than the sample's window, and malware that checks for this may behave differently. A fix using a logged-on-only Scheduled Task has been identified but not built.

    Known gap

    No packet capture yet

    The monitored profile has a placeholder capture job, but no capture.pcap is written. Network behaviour is read from screenshots and process logs.

    Known gap

    No egress kill switch

    Nothing cuts the monitored clone's network mid-run. Containment relies on the dedicated NAT segment, the fixed timeout and a forced power-off.

    Known gap

    No cross-case IOC table

    The database has one row per case. Asking "have I seen this domain before?" means searching each case's JSON files.

    Future work

    No watcher, Proxmox backend or SIEM feed

    Intake is read only when you run the command. The VM layer sits behind three functions so a Proxmox provider could slot in later. There's no CEF or syslog output.

    By design

    Nothing runs on its own

    No sender is blocked and no hash is submitted automatically. Every recommended action is yours to review and carry out.

    Safety built in

    Nothing to reuse

    Both clones are destroyed after every run, so there's never a dirty VM to open by accident.

    No path to your LAN

    The isolated clone has no network at all. The monitored clone's NAT network is never bridged to the home LAN.

    Content is data, not commands

    Pasted email text is written with a file tool, never interpolated into a shell, and agents record injection attempts as findings.

    Secrets stay local

    API keys live in a git-ignored .env. The VM password and filled-in answer file are ignored too.
